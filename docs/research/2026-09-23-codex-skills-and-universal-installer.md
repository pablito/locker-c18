# Codex skills discovery and universal installer

## Question

Resolve issue #4: verify Codex skill-discovery paths and installer support, verify the Vercel `skills` CLI (`npx skills add owner/repo`) across Codex, Claude Code, GitHub Copilot CLI, and OpenCode, and compare the CLI's lockfile schema with this repo's `skills-lock.json`.

## Summary / Verdict

- No: there is not one native file layout discovered by all four agents. `.agents/skills/` is native for Codex, Copilot CLI, and OpenCode, but not Claude Code; `.claude/skills/` is native for Claude Code, Copilot CLI, and OpenCode, but not Codex.
- Yes: one third-party installer command can cover all four: `npx skills add owner/repo --agent codex --agent github-copilot --agent opencode --agent claude-code` (or broader `--agent '*'`).
- That installer requires the Node/npm host path (`npx`); the package declares Node `>=22.20.0`.
- Codex current source loads repo `.codex/skills/`, repo `.agents/skills/`, user `$CODEX_HOME/skills` (deprecated; default `~/.codex/skills`), user `~/.agents/skills`, system/admin, bundled, plugins, and extra roots.
- OpenAI's public docs emphasize `.agents/skills` and `~/.agents/skills`, while source and the bundled `$skill-installer` still use `$CODEX_HOME/skills`; treat that as a documented/source discrepancy.
- Codex has no verified `codex skill install <repo>` terminal subcommand; it has the first-party `$skill-installer` skill with GitHub helper scripts.
- Vercel `skills` writes universal agents (Codex, Copilot, OpenCode) to `.agents/skills/<skill>`; in default symlink mode it also copies canonical `.agents/skills/<skill>` and symlinks Claude Code to `.claude/skills/<skill>`.
- This repo's `skills-lock.json` matches Vercel's project-local lockfile schema (`version: 1`, `skills[name].source/sourceType/skillPath?/computedHash`).

## Findings

### 1. Codex CLI skill discovery, installer, and `agents/openai.yaml`

OpenAI's public Codex skills page says Codex scans repository `.agents/skills` from CWD up to the repo root, user `$HOME/.agents/skills`, admin `/etc/codex/skills`, system bundled skills, and follows symlinked skill folders; it also describes `$skill-installer` rather than a terminal `codex skill install` command. Source: <https://developers.openai.com/codex/skills>.

Current Codex source adds more detail:

- `host_roots.rs` resolves project config-layer skill roots as `config_folder.join("skills")`; for a project layer, that config folder is the project's `.codex` folder, so this is `.codex/skills`. Tests explicitly create `repo/.codex/skills` and `repo/nested/.codex/skills` and assert they load. Sources: <https://github.com/openai/codex/blob/13869ca39e7ae749aad2018f4a3a5f67741286d9/codex-rs/ext/skills/src/host_roots.rs#L85-L94>, <https://github.com/openai/codex/blob/13869ca39e7ae749aad2018f4a3a5f67741286d9/codex-rs/ext/skills/src/host_roots_tests.rs#L447-L477>, <https://github.com/openai/codex/blob/13869ca39e7ae749aad2018f4a3a5f67741286d9/codex-rs/ext/skills/src/host_roots_tests.rs#L597-L675>.
- `host_roots.rs` marks `$CODEX_HOME/skills` as a deprecated user skills location kept for backward compatibility, also adds `$HOME/.agents/skills`, installs bundled system skills under `$CODEX_HOME/skills/.system`, and adds admin skills from the system config folder's `skills` directory. Sources: <https://github.com/openai/codex/blob/13869ca39e7ae749aad2018f4a3a5f67741286d9/codex-rs/ext/skills/src/host_roots.rs#L95-L119>, <https://github.com/openai/codex/blob/13869ca39e7ae749aad2018f4a3a5f67741286d9/codex-rs/ext/skills/src/host_roots_tests.rs#L279-L288>.
- `repo_agents_skill_roots` probes `.agents/skills` in directories from project root to CWD and tests assert root and nested `.agents/skills` load. Sources: <https://github.com/openai/codex/blob/13869ca39e7ae749aad2018f4a3a5f67741286d9/codex-rs/ext/skills/src/host_roots.rs#L137-L173>, <https://github.com/openai/codex/blob/13869ca39e7ae749aad2018f4a3a5f67741286d9/codex-rs/ext/skills/src/host_roots_tests.rs#L418-L443>.
- Bundled system skills are written under `CODEX_HOME/skills/.system`. Source: <https://github.com/openai/codex/blob/13869ca39e7ae749aad2018f4a3a5f67741286d9/codex-rs/skills/src/lib.rs#L49-L76>.
- The first-party `$skill-installer` skill says it installs Codex skills from curated OpenAI skills or another GitHub repo path into `$CODEX_HOME/skills/<skill-name>` (default `~/.codex/skills`). Its helper script supports `--repo <owner>/<repo> --path ...` and `--url https://github.com/.../tree/<ref>/<path>`. Sources: <https://github.com/openai/codex/blob/13869ca39e7ae749aad2018f4a3a5f67741286d9/codex-rs/skills/src/assets/samples/skill-installer/SKILL.md#L1-L54>, <https://github.com/openai/codex/blob/13869ca39e7ae749aad2018f4a3a5f67741286d9/codex-rs/skills/src/assets/samples/skill-installer/scripts/install-skill-from-github.py#L257-L338>.
- I could not verify a first-party terminal command like `codex skill install <github-repo>` in the public docs or source. The verified first-party path is the in-agent `$skill-installer` skill, not a shell subcommand. Sources: <https://developers.openai.com/codex/skills>, <https://github.com/openai/codex/blob/13869ca39e7ae749aad2018f4a3a5f67741286d9/docs/skills.md#L1-L3>.
- `agents/openai.yaml` is optional OpenAI metadata. The docs say it configures ChatGPT desktop UI metadata, invocation policy, and tool dependencies. The source constants set the metadata directory/file to `agents/openai.yaml`; the loader parses `interface`, `dependencies`, and `policy`; the interface fields include `display_name`, `short_description`, icons, `brand_color`, and `default_prompt`; policy includes `allow_implicit_invocation` and defaults implicit invocation to true when unset. Sources: <https://developers.openai.com/codex/skills>, <https://github.com/openai/codex/blob/13869ca39e7ae749aad2018f4a3a5f67741286d9/codex-rs/ext/skills/src/loader/mod.rs#L18-L22>, <https://github.com/openai/codex/blob/13869ca39e7ae749aad2018f4a3a5f67741286d9/codex-rs/ext/skills/src/loader/discovery.rs#L193-L218>, <https://github.com/openai/codex/blob/13869ca39e7ae749aad2018f4a3a5f67741286d9/codex-rs/ext/skills/src/loader/metadata.rs#L27-L56>, <https://github.com/openai/codex/blob/13869ca39e7ae749aad2018f4a3a5f67741286d9/codex-rs/skills/src/interface.rs#L13-L22>, <https://github.com/openai/codex/blob/13869ca39e7ae749aad2018f4a3a5f67741286d9/codex-rs/skills/src/model.rs#L22-L28>.

Sources: <https://github.com/vercel-labs/skills/blob/7407f3893ad4dceab546ac002c3ef806e4000c73/src/agents.ts#L869-L912>, <https://github.com/vercel-labs/skills/blob/7407f3893ad4dceab546ac002c3ef806e4000c73/src/installer.ts#L128-L178>, <https://github.com/vercel-labs/skills/blob/7407f3893ad4dceab546ac002c3ef806e4000c73/src/installer.ts#L321-L330>, <https://github.com/vercel-labs/skills/blob/7407f3893ad4dceab546ac002c3ef806e4000c73/src/installer.ts#L366-L447>.

### 4. Lockfile schema comparison

Vercel's project-local lockfile source defines `skills-lock.json` with `CURRENT_VERSION = 1`, top-level `{ version, skills }`, and per-skill entries containing required `source`, `sourceType`, and `computedHash`, plus optional `sourceUrl`, `ref`, `skillPath`, `subagents`, and `wellKnownDigest`. It writes sorted, timestamp-free JSON with a trailing newline. Source: <https://github.com/vercel-labs/skills/blob/7407f3893ad4dceab546ac002c3ef806e4000c73/src/local-lock.ts#L5-L60>, <https://github.com/vercel-labs/skills/blob/7407f3893ad4dceab546ac002c3ef806e4000c73/src/local-lock.ts#L102-L123>.

The same repo also has a different global lockfile `.skill-lock.json` with `CURRENT_VERSION = 3`, stored under `$XDG_STATE_HOME/skills/.skill-lock.json` or `~/.agents/.skill-lock.json`, whose entries use `sourceUrl`, `skillFolderHash`, `installedAt`, `updatedAt`, and optional dismissed/last-selected-agent fields. Source: <https://github.com/vercel-labs/skills/blob/7407f3893ad4dceab546ac002c3ef806e4000c73/src/skill-lock.ts#L6-L73>, <https://github.com/vercel-labs/skills/blob/7407f3893ad4dceab546ac002c3ef806e4000c73/src/skill-lock.ts#L175-L193>.

This repo's `skills-lock.json` currently has top-level `version: 1` and a `skills` object. Each inspected entry has `source`, `sourceType`, and `computedHash`; most GitHub entries also include `skillPath`, while `pre-mortem` and `the-immortals` omit optional `skillPath`. That matches the Vercel project-local `LocalSkillLockFile` schema, including optional omission of `skillPath`, and does not match the global `.skill-lock.json` schema because this repo uses `computedHash`, not `skillFolderHash`, and has no install timestamps. Source: local file `skills-lock.json`; Vercel schema sources above.
